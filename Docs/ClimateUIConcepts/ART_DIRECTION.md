# 改装、通道冰封与冰层季美术方案

2026-09-24 · 待选择的设计稿。入口：[动态预览](index.html)。

本次提供三版可操作 UI 与一套独立季节美术方案。底图取自项目已有的真实 Play Mode 画面，原字体与卡图沿用；新窗口、冰封和季节效果在浏览器中绘制。这些是放在实机画面背景上的交互设计稿，**不是已经接入 Unity 的新版实机截图**。新卡继续用废金属图占位。

本目录位于 Docs，未修改本轮之前的游戏脚本、Prefab、策划数值或存档。用户选定后再进行 Unity 接入。Unity shader 源码是落地草案；WebGL 对应版本已在浏览器中编译和实际绘制，Unity 版本尚未编译验收。

## 共用设计约束

- 保留原像素字体、黑底、双线窗框、“信息 / 改装”标签以及原地点、状态窗和底栏布局。
- 地点只出现能安装的项目：舱室为电缆、隔热棉；水域为牵引绳、电缆。不会为了凑齐版式显示不适用的空槽。
- 通道显示两端名字、共享冰封值及唯一浮标；两个方向不能出现可分别安装的浮标槽。
- 拖放与按钮是同一操作的两个入口。已装设备优先展示效果、耐久，详细耗损放在次级说明。
- 0 为正常、1–99 结霜但可通行、100–200 封锁；只有冰封值决定封锁。季节氛围不代替冰封状态。
- 体温危险继续由原状态窗表达；屏幕薄霜属于环境氛围，不意味着已经低体温。
- 演示使用钢锤除冰：5 分钟、冰封 −50、耐久 −1。150→100 仍封锁，100→50 才开放。未改动原规则。

## A：紧凑维护单

一项改装占一行。左侧为 80×100 的卡槽；右侧依次为名称/状态、效果、耐久、维护按钮。两行间用分隔线，不给整行铺大块灰色。

- 地点页：两项状态同时可见，适合快速查看与修补。
- 通道页：顶部冰封值和 100 阈值，中间为浮标；除冰和通行固定在底部。
- 冰封外观：细霜从四角爬入，低冰封值时只出现细小晶枝；达到 100 后增加短冰桥与文字标记。
- 优点：最接近现在的窗口，学习成本低，日常操作直接。
- 取舍：设备更像维护清单，拖入槽位的视觉存在感弱于 B。

## B：模块装配板

地点页将有效改装并排展示，空槽拥有斜纹、加号、卡牌名称与布置按钮。安装后显示原卡、设备状态及耐久。通道页使用“两端地点 → 同一通道 → 一个浮标”的明确关系。

- 地点页：两个槽位各自独立，不会把电缆、隔热棉混成一段说明。
- 通道页：只画一个浮标槽；两个端点名称不是第二个安装入口。
- 冰封外观：不对称的斜切晶片从外缘压进，晶面呈蓝灰，断面高光只占窄边。
- 优点：最能表达“把一张卡装到一个位置”，适合本项目的拖卡玩法。
- 取舍：比 A 多占一点横向空间；若未来有效改装超过 3 项，需要改成滚动槽位网格。

建议优先比较 B。其设备槽位和双向共享关系比较直观，冰封外观也能独立更换成 C。

## C：设备检修台

左侧列本站设备，右侧展开当前选中的一个设备。通道左侧为“冰封状态 / 融冰浮标”；说明、消耗、操作按钮有固定区域。

- 选中设备时侧边标记移动，不改变文字大小。
- 冰封页集中显示阈值与除冰操作；浮标页集中显示填充材料与耐久。
- 冰封外观：更完整的半透明厚冰壳，角部晶片更厚；冰壳内部保留原卡图，卡名与数值另放清晰条带。
- 优点：长说明和未来新增维护行为最容易安排，设备扩展空间大。
- 取舍：看另一个设备要多点一次；通道状态和浮标维护不能同时完整展开。

## 冰层季整体方案：冷色窗沿与漂浮冰晶

保持黑白像素桌面的主体识别度。将氛围集中在四角、屏幕外缘和未占用桌面；不额外铺一张风景插画，不把所有文字和图标统一染蓝。

### 1. 像素霜冻 shader

源码：[PixelFrostOverlay.shader](PixelFrostOverlay.shader)。当前项目使用 Built-in Render Pipeline，因此草案采用 uGUI 透明 Pass，包含 Stencil、RectMask2D 裁切和 AlphaClip 兼容入口。

结构：像素量化 → 固定噪声控制边缘生长深度 → Voronoi 晶面断边 → 冷色与高光混合 → 连续透明叠加。噪声图案固定，不每帧换种子，避免产生闪烁噪点。不得围绕文字挖硬边矩形空洞，否则会出现明显色块分界。

| 参数 | 建议起点 | 用途 |
| --- | --- | --- |
| `_FrostAmount` | 0–1，由季节阶段驱动 | 控制生长范围与覆盖 |
| `_PixelStep` | 4 屏幕像素 | 1920×1080 的整数像素颗粒；小卡建议 2 px |
| `_EdgeWidth` | 0.052–0.055 | 相对短边的最大边缘范围 |
| `_Opacity` | 0.75 | Unity 草案的最终透明度倍率 |
| `_ColdColor` | `#2E546E` 附近 | 暗部冰色，接近项目黑底 |
| `_LightColor` | `#BAE3ED` 附近 | 窄晶面高光 |
| `_Thaw` | 0→1 | 回暖时减淡冰层 |

浏览器使用同结构的 WebGL 演示，透明度为便于比较单独校准；不是 Unity shader 的像素级一致性验收。霜冻覆盖沿屏幕边缘连续变化；季节和日期文字绘制在效果上方，背景透明，不再以矩形遮罩隔断色调。

建议 shader 位于环境装饰层；文字、点击按钮、工具提示、存档/设置窗口位于更高层。RawImage/Image 的 Raycast Target 关闭。环境装饰用同一连续覆盖层；对卡图使用原始带 Alpha 的素材，不能把截图中的槽位底色一并当成卡图。

### 2. 屏幕与窗口边缘渐变

屏幕左右 7% 以内、上下 12% 以内连续渐变至透明。冷色渐变最大基础 Alpha 0.13，再乘阶段与场景倍率。中心保持原亮度，底栏采用统一底色，文字本身位于效果上方。

窗口边框仅增加薄冷色反光，信息正文不铺白雾。后续 Unity 接入可以在标题框角落使用同一个 shader 的小区域实例，避免整张全屏纹理重复覆盖每个窗口。

### 3. 粒子

| 场景 | 数量上限建议 | 像素尺寸 | 速度与行为 |
| --- | --- | --- | --- |
| 水域 | 38 个 | 2–4 px | 缓慢漂浮约 6.6 px/s，小幅横向摆动；不是雪花飘落 |
| 舱室 | 10 个，实际按低强度缩减 | 2 px 为主 | 约 3.4 px/s，极少悬浮凝晶 |
| 回暖 | 沿用对应场景预算 | 2×6 / 4×12 px | 少量向下融水，约 36 px/s |
| 工具除冰 | 每次 14 个 | 4 px | 1 秒内散开并消失，只在目标卡周围出现 |

环境粒子 Alpha 基值 0.15–0.45，再乘效果强度；手动暂停与系统“减少动态效果”均停止移动。模态窗口打开时，粒子位于其后。水下不使用大雪、地面积雪或整屏风暴线。

### 4. 阶段与室内外差异

| 阶段 | 对应世界日期 | 美术阶段系数 | 主要变化 |
| --- | --- | --- | --- |
| 常温 | 首次冰层季前 | 0 | 无季节霜冻、渐变、环境粒子 |
| 初临 | 第11–16天 | 0.35 | 边角薄霜，少量悬浮冰晶 |
| 极寒 | 第17–28天 | 1.00 | 边缘较深，晶面与粒子更多 |
| 回暖 | 第29–34天 | 0.42→0 | 冰层减淡，少量融水，渐变退去 |

预览的整体强度默认 70%，舱室另乘 0.42，水域乘 1。因而极寒水域强度为 0.70，极寒舱内为 0.294。正式接入可将舱室倍率进一步关联环境温度与隔热等级，但不改变玩法计算。冷暖切换建议 1.5 秒缓动，回暖当日按季节进度平滑衰减。

预览提供常温/初临/极寒/回暖四个代表状态，不运行24天的温度模拟；滑动冰封值独立于季节选择，用于检查残冰、提前融冰等情况。

### 5. 预算与验收边界

- 首选 1 个全屏霜冻层，960×540 离屏效果分辨率放大至 1920×1080，Point 过滤。
- 季节参数只在状态改变时更新。晶纹稳定，不做昂贵折射、GrabPass 或每卡一次全屏后处理。
- 同一帧可见通道卡共享小纹理/材质方案；选择后再根据 A/B/C 的冰形确定 Sprite 或 shader 组合。
- 不承诺本次浏览器预览能代表 Unity GPU 成本。Unity 接入后再检查真实 Game Camera、原相机 RenderTexture、窗口层级和目标设备帧耗时。
- 冰封与除冰反馈应分别检查 0、1、99、100、199、200；卡名/数值清晰，100 阈值一致，效果不拦截拖拽。
