# 存档与设置

## 玩家入口

- 主菜单「进入游戏」打开世界线列表；「设置」打开全局设置。
- 游戏内按 Esc，或点击底栏「设置」，打开设置的「游戏」页；顶部临时「保存」「退出」对象已从场景删除。
- 「游戏」页显示「时间线名称：」及最近保存信息，集中提供手动保存、读取保存点、返回主菜单和退出游戏。点击读取保存点只进入当前世界线已有的保存记录页，再次选择记录才载入；返回时回到设置的游戏页。保存退出、删除、改名、显示设置确认采用紧凑窗口，主要操作使用点缀色边框，危险操作只在悬停时提示红色。
- 自动保存完成在屏幕右上角提示 2.5 秒后淡出，失败提示保留 4 秒；提示不拦截鼠标、不暂停游戏。
- 世界线数量不设固定上限，列表复用可见行，支持拖动、滚轮和滚动条。
- 保存点不命名，以地点、游戏天数与时刻、实际保存时间和游玩时长辨认；不显示角色当前状态。
- 世界线名称可以手填，也可以点击名称旁「随机」。句式均以麦麦为主语，含单卡牌与双卡牌组合。
- 普通模式保留历史；自动记录默认 10 分钟一次、保留 10 个。退出时保存归入自动记录并参与同一轮换；手动记录永久保留，自动记录可转为手动记录。
- 硬核只保留最新进度，退出必须保存，死亡失效并删除数据。复制、分享副本强制成为普通模式。
- 分享导出到持久化目录下的 Shares 文件夹；接收者导入 `.wssave`，导入前显示摘要，不覆盖现有世界线。

## 数据与兼容

`Application.persistentDataPath/SavesV2/<run-id>/run.json` 为世界线索引；每个保存点为独立 GUID JSON 文件，内含原有各系统的完整数据分区。先写快照再原子发布索引，成功发布后才轮换旧自动记录。索引包含 SHA-256 校验值。索引写入失败不删除已有记录。

旧 LoadData/GameData0～3 只用于一次性迁移。迁移保留原文件，以 legacy-slot 标记防止重复迁移（含删除后的世界线）。新版读取缺失分区直接报错；只有旧档迁移沿用旧版本对缺失数据的默认初始化语义。

全局偏好保存在 Settings/settings.json，不参与回档。分享文件不包含全局设置；导入限制解压体积、条目数、文件名和允许的多态数据类型，拒绝未知格式版本。

新保存点记录现有底栏 SeasonText 的实际季节文字，显示“温和季·第 N 天 HH:mm”。旧档没有季节信息时只显示天数与时刻。当前工程未实现季节轮换；未来可通过 `SaveSystem.SeasonNameProvider` 接入真实日历，不需要修改存档 UI。

## 扩展方式

新增全局设置：在 `GameSettingsData` 增加字段，通过 `SaveSettingRegistry.Register` 注册 id、分类、显示名称与取值/更新回调。数值设置提供范围；开关或选项使用 value/change，可通过 reset 提供恢复默认值行为。UI 自动生成分类和设置行。显示模式有独立的 15 秒确认与回退流程。

创建流程：`NewRunOptions` 是草稿；界面调用 `SaveSystem.CompleteCreation`。未来人物特性界面通过 `NextCreationStep` 接收草稿并返回 true，完成选择后调用 `StartNewRun`。本次没有制作人物特性或自定义难度界面。

创建、读档、手动保存和退出通过持久化 `SaveRuntime` 执行，点击当帧锁定按钮并显示 `SaveTransition.prefab`，下一帧开始磁盘或场景工作。过渡层拦截鼠标，维持系统光标，完成后淡出；创建失败保留名称和模式草稿。新档直接使用刚生成的内存快照进入场景，不再写完后立即回读；场景切换取消前后的重复强制资源回收。

所有进度层从打开起至少显示 0.8 秒（使用真实时间，不受暂停影响），完成后再淡出；退出应用和失败路径也遵守最短时间。耗时操作不额外等待完整的 0.8 秒。

`ModalBackdrop.prefab` 从原休息窗口的 Modal 提取，休息窗口与 SaveHub 均引用同一 Prefab：黑色透明底板、全屏拉伸、拦截射线。窗口管理器在设置/世界线或过渡层显示期间停止桌面窗口焦点扫描，避免继续处理遮罩后面的射线结果。

「保存并退出」成功写入自动记录后才离开，写入失败留在原界面并恢复操作。返回主菜单和退出应用分别处理；Unity 编辑器内退出应用会停止 Play Mode，独立版本调用 `Application.Quit()`。

UI 成品：`Assets/Resources/Prefabs/UI/SaveHub.prefab`。窗口由现有 `CustomWindow` 派生，保留嵌套 `TopBar`；主要按钮以现有 `CustomWindowButton` 为基础，使用 `SaveHubButton` 驱动现有 `UI_HoveredFrame` 单层边框。悬停改变边框颜色，按下时文字轻微位移，按钮底色保持原色，普通按钮文字不反色；次级退出按钮使用较低明度，悬停时提亮。滚动区域使用现有 `ScrollView` 及其滚动条。采用和游戏 Canvas 相同的 2 pixels/unit，主体维持黑白灰，点缀色为 `#64DEAE`。保存记录采用 B 版时间轴和展开行，设置页采用 B 版固定左侧分类，创建页保留后续特性步骤接口。窗口拖动由 `SaveWindowDrag` 处理。`Tools/存档/生成界面` 可手动重建；会覆盖这个 Prefab 的手工布局修改，不在加载编辑器或普通游戏启动时自动生成 UI。

设置固定构图保存为嵌套 `Assets/Resources/Prefabs/UI/Settings/SaveSettingsPanel.prefab`，条目模板为同目录 `SaveSettingRow.prefab`。时间线名称、最新保存地点与时间、保存/读取按钮、次级返回/退出和继续游戏均可在 Prefab Mode 中编辑；标题使用现有 `Icons_Settings`。`SaveSettingsView` 只绑定数据、选择分类和实例化模板，`SaveSettingRow` 只绑定已有控件；不在运行时创建框体或用 IMGUI 绘制界面。注册新设置继续使用 `SaveSettingRegistry.Register`，分类自动出现，条目过多时内容区滚动，底部按钮保持固定。数值、开关、步进器和音量滑块沿用现有组件与滚动条素材；显示设置保留 15 秒回退确认。`SaveSettingsBuilder.cs` 是手动生成工具的一部分，不会在打开编辑器或运行游戏时自动重建。

鼠标由 `MouseManager` 统一控制。主菜单和游玩时使用原有自定义鼠标；存档窗口打开时交接给系统鼠标并隐藏自定义图像和等待图像，关闭或销毁时归还，保留等待状态。不在 Update/LateUpdate 中反复切换 `Cursor.visible`。

世界线入口页的固定布局、按钮、最新进度摘要、空列表和管理弹出菜单均序列化在同一 Prefab 的 `Worldlines` 层级，`SaveWorldlineView` 只绑定数据及复用滚动条目。每个世界线 ID 对应一个条目，最新保存点只提供地点和游戏时间摘要；保存记录在下一页显示。“载入游戏”统一先进入该世界线的记录页，再点击“读取此记录”进入游戏，硬核模式也经过此页，但只能读取唯一记录且不能删除或保留为手动记录。复制、分享、改名、删除收进次级“管理世界线”菜单；返回记录页的上一级时保留世界线选择和滚动位置。

## 验证入口

- `SaveFeatureValidation.Run`：独立临时目录中的存档仓库、损坏检测、分享与命名测试。
- `SaveFeatureValidation.BatchAll`：在独立测试工程中编译并运行 Play Mode 流程与 UI 渲染检查。报告输出到 Logs/SaveValidation。
- `SaveCreationValidation.Run`：验证创建连点、加载遮罩射线和光标、手动保存、保存返回主菜单、写入失败恢复和保存退出 Play Mode，并渲染小窗口。
- `SaveFeatureValidation.BuildStandalone`：构建 Windows Development 测试版本。
- Development Player 仅在传入 `--save-validation` 时启用独立数据目录中的读写/死亡回归测试；正常游戏启动不执行。

测试不会使用玩家的真实存档目录。关闭窗口能执行保存流程；操作系统强制结束进程或断电只能恢复最后成功保存的记录。
